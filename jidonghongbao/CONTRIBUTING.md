# 贡献指南

欢迎两类贡献：**活动改版后的打法更新**（最有价值）与**宿主兼容性实测**。

## 核心贡献场景：活动页改版

本 Skill 的选择器和战术时效性很强（京东玩法每日轮变、页面随时改版）。更新 `references/` 时请遵守：

1. **一切结论以实测为准**：新判据/新选择器必须在真实页面验证过再写，标注验证日期（如"2026-10-23 实测"）。
2. **推翻旧结论要显式标注**：保留被推翻的旧说法并标记"已推翻 + 原因"（防止其他贡献者按旧文档执行），参考 double11-2026.md 中登录判据、入口选择器的修正记录。
3. **战果必须可查证**：README 战绩区的每一项，需能在 references 战例中找到对应记录；无出处的数字不要提交。
4. **脱敏红线（PR 会被直接拒绝的情况）**：
   - 提交真实账号昵称、头像、订单信息
   - 截图未裁除账号信息与页面追踪码（底部小字串）
   - 提交 `runs/`、`.workbuddy-ai/` 等运行产物（已在 .gitignore，勿强制 add）
   - 提交任何 Cookie / Token / 凭据

## 跨宿主验收（合并前跑一遍）

1. **只读验收**：`使用 jidonghongbao，通过推广入口仅检查浏览器连接和活动页加载情况，不点击任何「抢」或领取按钮` → 应报告落地 URL、登录态判据、可领项，不产生点击。
2. **日常领取**：授权后领取一个红包/券，核对弹层面额与 quan.jd.com 到账。
3. **整点参与（可选）**：按 SKILL.md「标准时间表」实测一场，验证踩点刷新与弹层类型判别。

在 README 兼容性表中新增宿主时，请注明实测日期与结果；未实测的保持 ⬜ 状态。

## 入口链接

`references/` 中的推广入口带联盟参数（维护者的收入来源），**不接受替换他人联盟 ID 的 PR**；希望无归因可自行 fork 后替换（SKILL.md 已声明此选择权）。

## 提交格式

- SKILL.md 只放**宿主无关、年份无关**的通用规则；具体选择器、战例、日期数据一律进 `references/`。
- 文档措辞用"实测结论"，不引入"某某用户说"式的内部对话口吻。
