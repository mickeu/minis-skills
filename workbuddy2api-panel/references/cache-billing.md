# 大模型 API「缓存命中」通俗解释（含小浣熊实测）

## 什么是缓存命中

**缓存命中** = 你这次请求里的**一部分内容**（通常是系统提示词 + 历史对话 + 你输入的正文前缀），之前**原封不动**地发送给过同一个模型一次，平台服务器记得它，这次不用重新计算，直接拿上次算好的中间结果给你用。

## 为什么会有缓存

大模型处理一大段文字不是"读一遍"就完了，而是要**逐字逐句做大量计算**（前向传播）才能生成回答，这段计算很贵。当内容（System Prompt / 角色设定 / 长篇文档前缀）与之前**完全相同**时，平台不重算，直接复用上次的中间结果 → 省计算成本。

## 关键点

1. **不是"同一个会话"才命中，而是"内容一样"就命中**。换个新对话，只要系统提示词或正文前缀完全一致，照样命中。平台按**内容前缀**缓存，不看会话 ID。
2. **只对"前缀"有效**。缓存的是从开头算起的一段连续文字。如 `系统提示词 + 历史对话 + 新问题`，其中"系统提示词 + 历史对话"部分与上次完全一样就命中；中间任何一个字变了，后面缓存全部失效。
3. **API 会报告**。小浣熊接口返回字段 `usage.prompt_tokens_details.cached_tokens` 即缓存命中 token 数。

## 为什么关心它

缓存命中**通常应该更便宜**——平台省了计算成本，主流厂商（OpenAI/DeepSeek 官方/Anthropic 等）给缓存命中 token 打约 **0.1 折**。

## 小浣熊实测结论（2026-10-21）

**小浣熊（xiaohuanxiong.com）DeepSeek-V4.1-Flash 缓存命中基本按全价 0.25 倍率计费，几乎不打折。**

对照实验（账号1，模型 `sn-deepseek-v4-1-flash`，公式 `积分 = tokens × multiplier / 4000` 取整）：

| 请求 | prompt_tokens | cached_tokens | 实际扣费 |
|---|---|---|---|
| 冷 | 32271 | 0 | -3 |
| 热 | 32271 | 32256 | -2 |

- 冷：`32271×0.25/4000 = 2.017 → 取整 3` ✓ 全价
- 热：`(15×0.25 + 32256×x)/4000 = 2` → 反推缓存倍率 **x ≈ 0.248**，≈ 全价 0.25
- 余额 6947→6942 扣 -5，与账单 -3-2 吻合
- 1.9 万 token 测试冷热都撞 -2 取整桶，同样支持"缓存不打折"

### 结论
- **缓存命中 token 按≈全价计费，无 0.1 倍缓存折扣**
- 与平台模型目录一致：只暴露 `billing_multiplier` + `billing_discounts`，无独立缓存折扣字段
- 实际意义：在小浣熊上**不用特意为了"命中缓存省积分"复用长文本**——不省钱；但可获**响应变快**的好处。省钱应选限免模型（`sn-sensenova-6-8-flash` / `sn-deepseek-v4-1-flash-1017`，0 倍率至 10-31）。

## 实测方法（可复用）

- 用 Surge generic 脚本直连小浣熊网关 `https://xiaohuanxiong.com/api/web/llm/v2/chat/completions`，读 `$persistentStore` 里 `raccoon_openai_tokens_0` 的 access token
- 脚本固定从账号1（idx0）发请求，模型 `sn-deepseek-v4-1-flash`，max_tokens=8，stream=false
- 运行：`surge-cli script evaluate <js路径> generic <timeout>`
- 测试文件：`/var/minis/workspace/raccoon-single-shot.js`（改前缀+token量复用）、`/var/minis/workspace/raccoon-bills.js`（查账号1账单）

### 坑
- Surge evaluate 传超大 body（360KB+）会卡死超时，脚本应控制在 ~170KB 内
- 重复相同前缀会命中之前测试留下的缓存（导致"冷"请求实际已缓存），需换全新前缀测冷
- 并行/重复测试会在账号1产生多条 -2 干扰，注意用时间戳配对账单
- 扣费入账有 1-3 分钟延迟，且单次扣分取整，小 prompt 差异会被掩盖，需用 ≥3 万 token 的大 prompt 才能拉开
