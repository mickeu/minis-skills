## 0. 资源覆盖与口径

- `iOS系统布局/` 实际为 **75 个 ini**，6 个目录（320/375/414/568/667/736），而不是题述“7 分辨率、75 文件”。375 目录有 12 套；`9key_double` 与 `9key_double_ctod` 仅见于 568/667/736。任务列出的 13 套中 `9key_double` 无 375 文件，故其完整表采用最小可用 568 基准。

## 1. 字段语义（由全量取值与同坐标变体归纳）

|字段|事实语义|
|---|---|
|ID|逻辑键/控件资源 ID；同一功能跨布局复用。字符键并不保证 ID 等于 Unicode。|
|FRAME|控件命中矩形 `{{x,y},{w,h}}`。BACK_INSETS/DOWN_INSETS 是背景九宫格绘制内缩，不改变命中区。|
|STAT|状态可见性位掩码。值 31=低五位全开；同 FRAME 的 13/18、29/2 等互补变体证明运行时按状态位选择；64/128 是额外高位状态。**各 bit 的业务枚举名静态文件不足以唯一命名，待运行时枚举验证**。|
|POP|弹出候选/长按层配置索引；0/缺省表示无显式弹层。具体层号到内容的映射由布局加载器/资源表决定，不能等同“数量”。|
|DH|点划布局开关/点划键标记；`DH=1` 的同坐标键与普通变体互斥，控制点划皮肤或手势。|
|CODE|动作码/字符码。普通字符常缺省或使用 ASCII/Unicode；功能码由控制器解释。静态可确认：同 ID、DOWN_NAME、坐标可跨键盘追踪动作；不可把所有 CODE 直接转 Unicode。|
|CENTER|键心显示/输入字符；DOWN_NAME 为按下气泡文字。FORE_STYLE 可完全替代文字显示。|
|BACK_STYLE|背景样式资源 ID，而非颜色值。6xx 多为键帽、4xx 面板、5xx 列表；最终图片/拉伸方式由主题 `style.ini`→`image.ini` 解析。|

- 320/375/414 是竖屏宽度档；568/667/736 是横屏宽度档。布局不是统一 `width/375` 仿射缩放，而是离散模板：功能列、左右留白、键宽和间隙分别取整。

### 差异结论

- 经典布局提供 `*_ctod`（候选栏到点划/切换态）配套文件；点划布局提供 `*_dh`、`*_dh_no_symbol`、`*_dh_part` 与 `bihuakey_double` 等显式点划变体。
- 判定点划不能只看文件名：键级 `DH=1` 与同 FRAME 的普通键共同构成运行时替换槽。
- `Symbol.plist` 定义符号分类/内容数据；符号面板 ini 只定义分类键、网格 FRAME 与动作 ID。内容与几何分离，移植时应保留“符号数据源 + 面板模板”两层。
