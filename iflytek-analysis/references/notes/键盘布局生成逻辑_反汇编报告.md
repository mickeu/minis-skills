# 键盘布局生成逻辑：反汇编报告

## 结论

布局链路是：`INI 文本 → 分节二维字典 → KeyStructGenerator/CandKeyStructGenerator → 运行时结构对象`。INI 解析器逐行读入，跳过注释/空行；`[SECTION]` 建立当前节，普通行按首个 `=` 分成 key/value；两个布尔参数分别控制键名和节名小写。主键生成器并非直接写 ivar，而是创建 `KeyStruct` 后逐字段调用 setter；几何字符串交给 UIKit 字符串转换函数，insets 再据 key frame 裁出真正子图 frame。缺失的可选字段不写入；整数类字段经 `integerValue`，文本字段保留 NSString。

> 地址采用原始 VA。给定 `.asm` 把切片重定位为 `0x100000000`，故文中函数内地址 = 函数 VA + 汇编显示偏移。

## 1. `+[IniFileParser parseIniFileToDictionaryWithFilePath:lowercaseKey:sectionLowercase:]`

- VA：`0x10020d6fc`；参数 `x2=path, w3=lowercaseKey, w4=sectionLowercase`。
- `0x10020d728` retain path，空路径直接返回 nil（`+0x34 cbz`）。
- `+0x38..0x50` 由路径读成字符串，随后创建逐行枚举器；外层返回容器是可变字典。
- 循环 `+0x74..0x1c0`：取下一行；`+0x7c` 的位测试过滤不可处理行；`+0xc0..0xcc` 再过滤注释/空白。可见样例 `#` 行不会进入字典。
- 节头：解析器维护 `currentSectionName`(x23) 与 `currentSectionDict`(x26)。遇到下一节或 EOF，`+0x150..0x198` 将上一节字典写入根字典。若 `sectionLowercase` 为真，先对节名调用 `lowercaseString`（`+0x154..0x178`）；否则使用原节名。
- 键值：`+0xe4..0xfc` 从当前行提取 key/value；`+0x100` 检查 `lowercaseKey`，真时 `+0x104..0x124` 对 key 调 `lowercaseString` 后 `setObject:forKey:`，假时 `+0x134..0x140` 原样写入。
- `+0x198..0x1c0` 继续取下一行；EOF 后复制/固化根字典并返回。

返回结构：

```objc
@{ @"INPUT": @{ @"ID": @"2002", ... },
   @"PANEL": @{ @"FRAME": @"{{0,66},{375,216}}", ... },
   @"KEY1":  @{ @"ID": @"6058", @"CENTER": @"q", ... } }
```

值均为字符串；重复 section 名按 NSDictionary 语义后写覆盖前写。样例中重复 `[KEY15]`、`[KEY22]`、`[KEY34]` 因而最终只保留最后一次同名节，这是布局用 `STAT` 表达互斥状态、同时允许配置覆盖的关键行为。

可移植实现：

```c
Dict *parse_ini(path, bool lowerKey, bool lowerSection) {
    String *text = read_text(path); if (!text) return NULL;
    Dict *root = dict_new(), *sec = NULL; String *secName = NULL;
    for (String *raw : enumerate_lines(text)) {
        String *line = trim(raw);
        if (!line.len || line[0]=='#' || line[0]==';') continue;
        if (line[0]=='[' && line[line.len-1]==']') {
            if (sec) dict_set(root, lowerSection?lower(secName):secName, sec);
            secName = substring(line,1,line.len-2); sec=dict_new(); continue;
        }
        if (!sec) continue;
        ssize_t eq=index_of(line,'='); if (eq<0) continue;
        String *k=trim(substring(line,0,eq));
        String *v=substring(line,eq+1,line.len-eq-1); // 空值合法
        dict_set(sec, lowerKey?lower(k):k, v);
    }
    if (sec) dict_set(root, lowerSection?lower(secName):secName, sec);
    return immutable_copy(root);
}
```

## 2. `+[KeyStructGenerator structWithDic:]`

VA `0x10013e4a4`。`x2` 为单个 KEY section 字典。`+0x30` retain，nil 返回 nil；`+0x40..0x64` 分配并 init `KeyStruct`。其后模式固定为 `objectForKey:` → 转换 → setter。

### 2.1 基础字段及几何

| INI | 证据（函数内偏移） | 转换/目标 |
|---|---:|---|
| ID | `+0x78..0xa4` | 取值后写 `setSid:`；样例 `6058` |
| BACK_STYLE | `+0xa8..0xd4` | 生成背景 StyleStruct，写 `backStruct` |
| FRAME | `+0x118..0x180` | 字符串转换为四个 double（d0-d3），写 `setFrame:` |
| BACK_INSETS | `+0xe8..0x180` | 转 UIEdgeInsets；计算背景子 frame |
| FORE_STYLE / FORE_INSETS | `+0x1a0..0x268` | 可选前景 StyleStruct；裁 frame 后挂到 `foreStruct` |
| UP_STYLE / UP_INSETS / UP_NAME | `+0x26c..0x384` | 可选 up 子结构 |
| DOWN_STYLE / DOWN_INSETS / DOWN_NAME | `+0x388..0x4a0` | 可选 down 子结构 |
| RIGHT_STYLE / RIGHT_INSETS / RIGHT_NAME | `+0x4a4..0x59c` | 可选 right 子结构 |

`FRAME` 调用点 `+0x134` 返回 d0-d3，ABI 形态与 `CGRectFromString(NSString *)` 完全一致：`{{x,y},{w,h}} → (x,y,w,h)`，不存在手工逗号切分。INSETS 路径同理：转换函数返回四个 double，再按 UIKit 的 `UIEdgeInsetsMake(top,left,bottom,right)` 内存顺序参与运算。配置文本虽常写成“上、右、下、左”，实际计算证据为：

```c
child.x = key.x + inset.left;
child.y = key.y + inset.top;
child.w = key.w - inset.left - inset.right;
child.h = key.h - inset.top  - inset.bottom;
```

在 `+0x158..0x16c`，保存的 d8/d9/d10/d11 与 key frame 做两次加法、两次减法；`+0x238..0x24c` 及后三组完全重复。由样例 `{8,3,6,3}` 得背景 frame `(3,8,w-6,h-14)`，证明文本四元组应按 `{top,left,bottom,right}` 解释，而不是“上右下左”。

### 2.2 子结构构造

每个视觉层均为相同模板：

1. STYLE 存在才创建 StyleStruct；
2. style 字符串经 `mapStringToString:` 标准化；
3. INSETS 存在则由 key frame 裁剪；
4. NAME 存在写文字；
5. 挂到 KeyStruct 对应属性。

FORE/UP/DOWN/RIGHT 均可独立缺省。`DOWN_NAME=Q` 等是显示文字；`CENTER=q` 是提交/中心内容，两者不可混为同一字段。

### 2.3 POP、DH、STAT、CODE

| 字段 | 存储结论 | 证据 |
|---|---|---|
| CENTER | NSString/内容对象，写 `content` | `+0x5a0` 后字符串存在性判断及内容 setter |
| POP | 整数，缺失默认 `-1`，写 `popKey` | `+0x968..0x9a4`；空时 `mov w2,#-1` |
| DH | 整数，缺失默认 `0`，写 `dhKey` | `+0x9a8..0x9e4`；空时 `mov w2,#0` |
| STAT | 无条件 `integerValue` 后写 `stat` | `+0x9e8..0xa10` |
| CODE | 整数，写 `code` | 后段数字转换/setter；样例 0/2/5/121/133 等 |
| TAG | 整数，缺失保持默认 0，写 `tag` | 后段可选数字 setter |

`POP`/`DH` 保存的是引用编号，不会在这里解析 `[POP1]`/`[DH1]`；后续布局装配阶段据编号关联弹窗/动态提示结构。`STAT` 是位掩码；同 frame 多个键以不同 STAT 共存（例如样例 KEY20/21/22 的 31/64/128），由上层按键盘状态筛选。

### 2.4 `KeyStruct` 对象布局

属性 getter/setter 符号给出稳定的逻辑字段；直接 ivar 偏移未在生成器中出现（全部经 objc_msgSend），故下面“偏移”区分对象 ABI 与语义槽位：

```c
struct KeyStructLogical {
  Obj *backStruct, *foreStruct, *upStruct, *downStruct, *rightStruct;
  Obj *content;
  int64_t sid, locationSid;
  int64_t popKey, dhKey, code, stat, tag;
  CGRect frame;
};
```

事实：setter 地址分别为 `setBackStruct 0x1001b9fdc`、`setForeStruct 0x1001ba000`、`setUpStruct 0x1001ba024`、`setDownStruct 0x1001ba048`、`setRightStruct 0x1001ba06c`、`setSid 0x1001ba0a0`、`setPopKey 0x1001ba0e8`、`setDhKey 0x1001ba10c`、`setCode 0x1001ba130`、`setStat 0x1001ba150`、`setFrame 0x1001ba178`、`setTag 0x1001ba1a0`。待验证：精确 ivar byte offset，需再反汇编这些 setter（通常单条 `str` 可直接恢复）。

## 3. `+[KeyStructGenerator mapStringToString:]`

VA `0x10013f01c`。函数 retain 输入，先检查字符串中是否含分隔标记；命中时按标记拆分并取指定片段，否则返回原串的复制/保留结果。其用途不是数值映射表，而是把 STYLE/NAME 配置中的复合字符串规整为当前运行时使用的单个字符串。生成器在各 STYLE 分支调用它，再传给 StyleStruct；普通 `CENTER`、整数不经过它。

事实依据：控制流只有字符串匹配、按索引取子串和 retain/release，没有字典查表或 switch 数值分支。具体分隔字符的 CFString 常量未从给定切片直接解出，标为待验证；复刻时应先保持原串，仅在遇到资源配置中的复合形式时实现同等拆分。

## 4. `+[CandKeyStructGenerator structWithDic:]`

VA `0x1002f954c`，主体仅 `0x228` 字节，明显小于主键生成器。创建 `CandKeyStruct` 后顺序赋值：

| 字段 | 转换 | 对应属性 |
|---|---|---|
| ID | integer | sid |
| BACK_STYLE | string | backStyleName |
| FORE_STYLE | string | foreStyleName |
| FRAME | CGRectFromString | frame |
| CONTENT_INSET | UIEdgeInsetsFromString | contentInset |
| WIDTH_RANGE | 几何范围转换 | widthRange |
| AUTOSIZE | bool/integer | autosize |
| STAT | integer | stat |
| CODE | integer | code |
| TAG | integer | tag |

证据是 `+0x48..0x204` 十组连续的 `objectForKey:`/转换/setter；属性符号集中于 `CandKeyStruct 0x10019a3bc..0x10019a5bc`。候选键不构造 UP/DOWN/RIGHT、POP、DH、CENTER 等主键交互结构；它直接保存样式名和候选内容布局约束，支持 `contentInset/widthRange/autosize`，适合候选文字宽度变化。候选生成器也不执行主键的 insets→子 frame 裁剪。

|---|---|---|---|

## 6. 完整数据流

```text
26cnkey.ini
  │ UTF-8/文本读取，逐行枚举
  ▼
IniFileParser
  ├─ [KEYn] ───────────────┐
  ├─ key=value             │ lowercaseKey 可选
  └─ sectionLowercase 可选 │
  ▼                        │
NSDictionary<section, NSDictionary<key, NSString*>>
  │                        │
  ├─ KEY* → KeyStructGenerator ─→ KeyStruct + 视觉子 Struct
  ├─ 候选键 → CandKeyStructGenerator → CandKeyStruct
  ├─ POPn → 弹窗结构生成器
  └─ DHn  → 动态提示结构生成器
             │
             └─ popKey/dhKey 编号在装配阶段关联
```

## 7. 可移植伪 C

```c
Key *make_key(Dict *d) {
    if (!d) return NULL;
    Key *k = new_key();
    k->sid = to_i64(d["ID"]);
    k->frame = CGRectFromString(d["FRAME"] ?: "{{0,0},{0,0}}");

    k->back  = make_layer(d["BACK_STYLE"],  NULL,
                          d["BACK_INSETS"], k->frame);
    k->fore  = make_layer(d["FORE_STYLE"],  NULL,
                          d["FORE_INSETS"], k->frame);
    k->up    = make_layer(d["UP_STYLE"],    d["UP_NAME"],
                          d["UP_INSETS"],   k->frame);
    k->down  = make_layer(d["DOWN_STYLE"],  d["DOWN_NAME"],
                          d["DOWN_INSETS"], k->frame);
    k->right = make_layer(d["RIGHT_STYLE"], d["RIGHT_NAME"],
                          d["RIGHT_INSETS"],k->frame);

    k->content = d["CENTER"];
    k->popKey = d["POP"] ? to_i64(d["POP"]) : -1;
    k->dhKey  = d["DH"]  ? to_i64(d["DH"])  : 0;
    k->stat   = to_i64(d["STAT"]);
    k->code   = to_i64(d["CODE"]);
    k->tag    = to_i64(d["TAG"]);
    return k;
}

Layer *make_layer(String *style, String *name, String *insetText, CGRect base) {
    if (!style) return NULL;
    Layer *s=new_layer();
    s->style=map_style_string(style);
    s->name=name;
    UIEdgeInsets e = insetText ? UIEdgeInsetsFromString(insetText)
                               : UIEdgeInsetsZero;
    s->frame=(CGRect){base.x+e.left, base.y+e.top,
                     base.w-e.left-e.right, base.h-e.top-e.bottom};
    return s;
}

CandKey *make_cand_key(Dict *d) {
    if (!d) return NULL;
    CandKey *k=new_cand_key();
    k->sid=to_i64(d["ID"]); k->backStyle=d["BACK_STYLE"];
    k->foreStyle=d["FORE_STYLE"];
    k->frame=CGRectFromString(d["FRAME"]);
    k->contentInset=UIEdgeInsetsFromString(d["CONTENT_INSET"]);
    k->widthRange=parse_range(d["WIDTH_RANGE"]);
    k->autosize=to_bool(d["AUTOSIZE"]);
    k->stat=to_i64(d["STAT"]); k->code=to_i64(d["CODE"]);
    k->tag=to_i64(d["TAG"]); return k;
}
```

## 8. 待验证项与下一步

1. 反汇编 `KeyStruct`/`CandKeyStruct` 全部 setter，读取 `str [x0,#imm]`，补齐精确 ivar byte offset。
2. 解出 `0x101688xxx` CFString 引用，逐项绑定主生成器中的所有常量键名，确认 RIGHT/CENTER/CODE/TAG 的确切分支地址。
3. 对 `mapStringToString:` 的常量做 Mach-O `__cfstring` 指针解析，确定复合字符串分隔符及取第几段。
4. 对重复 section 做单元测试，验证当前版本确为后写覆盖；这是从 NSDictionary 写入数据流得出的事实，但建议动态跑一次解析器固化。
5. 用 `{8,3,6,3}` 和 `{{0,0},{37.5,56}}` 动态验证输出背景 frame 应为 `{{3,8},{31.5,42}}`，可排除配置文档把四元组误标成“上右下左”。
