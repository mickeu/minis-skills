# 键盘映射核心逻辑：讯飞输入法 v15.0.3606 反汇编报告

> 对象：`phn::KeyLayout / phn::LayoutImp`（ARM64）。下列 VA 均为原 Mach-O 虚拟地址；报告依据完整函数切片复核，而非只依据最初 0x500 字节素材。错误码常量 `0x1adb2/0x1adb4` 的语义名称未恢复，本文统一写作 `E_PARAM/E_STATE`。

## 0. 结论先行

1. **坐标不是运行时搜索矩形，而是先预生成中心点表，再用键码直接索引。** `GetLayoutCoord` 以 `key-'a'` 或 `key-'2'` 取 `LayoutCoord`；26 键生成 26 个 `(x,y)`，9 键生成 9 个 `(x,y)`。证据：`0x1010306a8` 的范围减法与 `index<<3`；`Set26KeyCoord` 连续写 `[x2,#0..200]`；`Set9KeyCoord` 写 `[x2,#0..64]`。
2. **点击纠错是方向敏感的曼哈顿距离模型，不是欧氏高斯。** 先归一化 `dx=(centerX-touchX)*100/keyW`、`dy=(centerY-touchY)*100/keyH`，再按目标字母的方向类别选择 `|dx|`、`|dy|` 或 `|dx|+|dy|`，乘方向权重、舍入，最后乘序位衰减。证据：`0x1010327c4..0x1010328a0`（原函数 VA，下同）整数差、`sdiv`；`0x101032850..0x1010328cc` 的 `fabs`/相加路径。
3. **滑动纠错沿用中心偏差，但增加分段门限并计算乘积惩罚。** 26 键函数用四类方向规则和三个浮点阈值；9 键专门算法只按横向偏差分桶：`|dx|>=36→16`、`>=26→32`、`>=16→48`。证据：`0x101032fa8+0x188..0x1b8`。
4. **模糊拼音是 256 项字节代换表。** 先恒等初始化，再按 bitmask 覆盖；确证包括 `z↔zh`、`c↔ch`、`s↔sh`、`n↔l`、`f↔h`、`r↔l`、`k↔g` 及韵母类。所谓 `zh/ch/sh` 用内部单字节码 `0xe2/0xe0/0xe1` 表示，不是两个 ASCII 字符。
5. **双拼分默认表与自定义图两条路径。** 默认 `DPKeyMapping` 使用静态编码表；配置存在时 `CustomDPKeyMapping` 查动态容器；`DPSyllablToOriLabel` 将内部声韵码还原为原始键标签，`DPFuzzyMapConvert` 在双拼内部码与 ASCII/特殊码间做模糊替换。
6. **`LayoutImp` 是薄适配/策略层。** 对象仅含 vptr 与 `KeyLayout*`；坐标接口尾调用核心对象，映射接口根据输入法类型、布局合法性和纠错开关调用 `KeyLayout`，`KeyMapConvert` 再在两种参数形态间分派。

## 1. 数据结构恢复

### 1.1 `Layout`（确证）

`VerifyLayout(0x101030848)`、坐标设置函数对同一参数的访问给出：

```c
typedef struct Layout {           // >= 28 bytes
    int32_t row0_x;               // +0
    int32_t row0_y;               // +4
    int32_t row1_x;               // +8
    int32_t row1_y;               // +12
    int32_t row2_x;               // +16
    int32_t row2_y;               // +20
    uint16_t key_h;               // +24
    uint16_t key_w;               // +26
} Layout;
```

字段名按数据流命名：`Set*Coord` 对三个 `(x,y)` 分别加半键宽/高形成三行起始中心；`GetCorrectProp` 用 `+26` 除横向差、`+24` 除纵向差。`VerifyLayout` 要求宽高非零，并检查各行坐标/边界关系。

### 1.2 `LayoutCoord`（确证）

```c
typedef struct LayoutCoord { int32_t x, y; } LayoutCoord; // sizeof=8
```

证据：所有生成函数使用 `stp wX,wY,[x2,#8*n]`；查询函数 `ldp w8,w9` 后原样写出。

### 1.3 `InputKey`（高置信）

```c
typedef struct InputKey {
    uint16_t label[/*NUL 终止*/];  // +0，内部 UTF-16/16-bit token 串
    // 对单触点路径：
    int32_t x;                    // +4
    int32_t y;                    // +8
    // +12 起还有输入类型/轨迹元数据（LayoutImp 访问 +12,+16,+20,+24,+28）
} InputKey;
```

注意：`label` 与 `x/y` 看似重叠，说明公开类型极可能是 union/变长 ABI（不同 input-kind 对应不同视图），不能机械声明为平铺结构。事实是纠错函数从 `+0` 读首个 `uint16_t`，从 `+4/+8` 读触点；`LayoutImp::GetKeyMapping(0x1010356cc)` 还读 `+12..+28`。建议移植时显式拆成 tagged union。

### 1.4 `OutputMap`（确证字段 + 保守命名）

```c
typedef struct OutputMap {
    uint8_t  header[32];
    int32_t  prop[/*至少若干项*/]; // +0x20 起；纠错权重/代价数组
    // KeyMapping 另写 +0x3c(60) 附近状态/数量
} OutputMap;
```

证据：点击与滑动纠错均以 `out+0x20+4*i` 写分值；`KeyMapping` 访问 `+60`。其前 32 字节的精确字段边界待验证，不能伪造。

### 1.5 `KeyMap` / `KeyMapCovParam`

`keylayout_getmapcommon_sub(short,char,char,short*,int*,const KeyMap*)` 对 `KeyMap` 使用固定步长记录，读取记录首字节/映射载荷；`LayoutImp::KeyMapConvert` 的参数结构确证如下：

```c
typedef struct KeyMapCovParam {
    int32_t mode;      // +0：0/1 两种转换方向
    const void *src;   // +8
    int32_t count;     // +16
} KeyMapCovParam;
```

`KeyMap` 单记录的完整 ABI 因静态表缺少类型符号，暂写为逻辑结构：`{inputToken, condition/type, outputToken(s), flags}`；报告不把猜测偏移冒充事实。

### 1.6 `KeyLayout` 与 `LayoutImp`

```c
typedef struct KeyLayout {
    void *custom_begin;      // +0
    void *custom_root;       // +8
    void *custom_end;        // +16/+24（树/序列容器节点状态）
    float global_scale;      // +32 = 1.0f
    uint8_t custom_enabled;  // 邻近 +40（配置后读取）
    void *allocator64;       // +56，构造时分配 64 字节并初始化
    // 后续成员由 STL 容器承载
} KeyLayout;

typedef struct LayoutImp {
    void *vptr;              // +0
    KeyLayout *core;         // +8
} LayoutImp;
```

证据：`KeyLayout::C2(0x101030138)` 清零前 32 字节、写 `+32=0x3f800000`、分配 64 字节并存 `+56`；`LayoutImp::C1(0x101035688)` 一次 `stp vptr,x1,[x0]`。

## 2. 坐标建立与查询

### 2.1 `Set9KeyCoord` — VA `0x101030d40`

令三行锚点为 `(rx[i],ry[i])`，键宽高为 `W/H`：

```c
for (r=0; r<3; ++r)
  for (c=0; c<3; ++c) {
    coord[r*3+c].x = trunc(rx[r] + W*0.5 + c*W);
    coord[r*3+c].y = trunc(ry[r] + H*0.5);
  }
```

函数使用 double 做半宽/半高相加，再转 float、`fcvtzs` 截断为整数。键码查询域不是 1..9，而是 `'2'..'9'` 加一个特殊索引：`GetLayoutCoord` 对数字路径做范围与表索引转换；9 键滑动函数明确识别 `'7'/'9'` 边缘键。

### 2.2 `Set26KeyCoord` — VA `0x101030b34`

三行键数固定为 10/9/7，连续产生 26 个中心：

```c
for (c=0;c<10;c++) out[c]    = center(row0,c);
for (c=0;c< 9;c++) out[10+c] = center(row1,c);
for (c=0;c< 7;c++) out[19+c] = center(row2,c);
```

布局锚点允许每行独立横移，因此可表达 QWERTY 第二/三行缩进。连续写至 `+200=25*8` 是 26 项的直接证据。

### 2.3 `GetLayoutCoord` — VA `0x1010306a8`

- 校验 `layout/out`；
- 字母路径接受 `a..z`，索引 `key-'a'`，调用/使用 26 键中心表；
- 数字路径按 9 键编码转换后索引；
- 不在合法域返回错误码；
- 输出恰为两个 `int32_t`。

这说明完整触摸链应是：UI 命中获得 nominal key（或引擎枚举候选 key）→ `GetLayoutCoord` 取得每个候选键中心→纠错函数计算候选代价。它不是给任意 `(x,y)` 做二维命中测试的接口。

### 2.4 `VerifyLayout` — VA `0x101030848`

检查项可从访问序列确定：空指针、`key_w/key_h != 0`、三行锚点与尺寸构成合法区域、坐标不能出现逆序/越界；失败写日志并返回 `0x1adb2`，成功返回 0。调用者必须先校验，纠错函数中的除法没有替调用者容忍零尺寸。

## 3. `KeyMapping`：按键到标签/音节

### 3.1 主函数 — VA `0x101030e48`

签名：

```c
int KeyMapping(int mode, const _KeyLabel& label,
               OutputMap *out, int inputCount,
               const InputKey *in);
```

控制流：

1. 参数与模式校验；清理/初始化 `OutputMap`。
2. 从 `_KeyLabel` 取得 16-bit 标签序列；依输入模式选择普通拼音、9 键、多语种或双拼分支。
3. 普通拉丁标签以 `a..z` 范围检查；9 键标签保留一键多字母的映射集合。
4. 对每个映射 token 调 `keylayout_getmapcommon_sub(0x1010322e0)`，将命中写到临时 `short[]`，同时更新数量。
5. 双拼模式调用 `DPKeyMapping(0x101031890)`；存在自定义方案时切到 `CustomDPKeyMapping(0x101031be0)`。
6. 根据输入事件类型调用 `GetCorrectProp`、`GetSwipeCorrectProp` 或 9 键特化，权重写入 `OutputMap::prop[]`。
7. 返回 0 或参数/状态错误码。

26 键与 9 键的本质差异：26 键 nominal key 一对一对应字母，中心表 26 项，纠错可在字母邻域内展开；9 键 nominal key 一对多对应拼音字母集合，中心表 9 项，滑动纠错只调同一数字格附近的分值，不先假设唯一字母。

### 3.2 公共子函数 — VA `0x1010322e0`

签名中的前四个标量分别保持当前 16-bit 标签、两个 8-bit 条件/模式和目标缓冲。函数线性扫描 `KeyMap` 表：比较输入 token 与条件，命中后将映射 token 追加到 `short *dst`，通过 `int *count` 返回项数；支持一键多输出及特殊 token。它是普通拼音、双拼转换、多语言扩展共享的“表驱动展开器”，并不计算概率。

伪 C：

```c
int map_common(int16_t in, uint8_t mode, uint8_t flags,
               int16_t *dst, int *n, const KeyMap *tab) {
    if (!dst || !n || !tab) return E_PARAM;
    for (const KeyMap *p=tab; !is_sentinel(p); ++p) {
        if (p->input != in || !condition_match(p,mode,flags)) continue;
        for (unsigned j=0;j<p->nout;j++) dst[(*n)++] = p->out[j];
    }
    return 0;
}
```

### 3.3 天城文扩展 — VA `0x101031390`

`KeyMappingDevanagari` 保持相同 `OutputMap` 管线，只换标签合法域和静态 `KeyMap`。这证明架构把“语言 token 表”和“几何纠错”解耦：新增语种不需要重写坐标模型。

## 4. 双拼映射

### 4.1 `DPKeyMapping` — VA `0x101031890`

输入两个整数（方案/状态与键 token），输出两段 `int16_t` 序列。函数按模式选择默认声母、韵母静态表，先查第一键得到 initial，再结合第二键/零声母规则得到 final；特殊内部码保留供后续音节转换。输出 NUL 终止。

### 4.2 `DPSyllablToOriLabel` — VA `0x101033348`

将内部双拼音节还原为原始键标签。其核心不是拼接 UTF-8，而是遍历 `uint16_t` token，识别 `z/c/s` 与内部 `zh/ch/sh` 特殊码及韵母编码，再逆查声母键/韵母键写两个目标数组。因此候选引擎可以保留“规范音节”和“用户实际键序列”两套表示，前者查词，后者用于回显、学习和纠错对齐。

### 4.3 `DPFuzzyMapConvert` — VA `0x101033188`

逐个 16-bit token 转换，明确规则：

```c
if (flags & 0x2) { c↔0xe0; s↔0xe1; z↔0xe2; } // ch/sh/zh 内部码
if (flags & 0x4) { /* 对 0xe4..0xf9 的若干韵母码成对转换 */ }
if ('A'<=t && t<='Z') t = static_upper_map[t-'A'];
```

输出始终补 0。第一组由 `cmp c/s/z` 与 `0xe0/0xe1/0xe2` 双向分支直接确证；第二组跳转表确证存在多对特殊韵母码，具体语义名需结合音节码表验证。

### 4.4 自定义覆盖

`SetDpCustomKeyMap(0x101033818)`：

- 接收 `std::string`；判空并解析配置；
- 校验键为 `a..z`、分隔符/字段数量；
- 解析到临时 STL 容器，只有整体通过后才替换对象中旧容器（避免半更新）；
- 设置自定义启用状态；失败保持旧默认/旧配置并返回错误。

`SetDpCustomAuxiMap(0x1010343b4)` 以同样事务式方式解析辅助规则，函数更长是因为预置/归一化了大量 0x100 字节槽和别名表。

`CustomDPKeyMapping(0x101031be0)` 先查 `KeyLayout` 动态容器；命中即产生自定义 initial/final，未命中或未启用则回落默认路径。可移植实现应遵循明确优先级：

```c
map = custom_enabled && custom.contains(key,state)
    ? custom.lookup(key,state)
    : default_dp.lookup(key,state);
```

`LayoutImp::SetDpCustomKeyMap/AuxiMap`（`0x101035b1c/0x101035c04`）仅验证 `core` 并转发，说明配置所有权在 `KeyLayout`。

## 5. `GetFuzzypyMap` 模糊拼音

VA `0x101030290`，签名 `int GetFuzzypyMap(int enable, int mask, uint8_t out[256])`（参数语义按数据流命名）。先初始化恒等表，随后仅在总开关 bit16 打开时根据 mask 改写。内部复合声母码：`CH=0xe0, SH=0xe1, ZH=0xe2`。

### 5.1 确证覆盖表

| mask bit | 表改写（源→目标） | 语义 |
|---:|---|---|
| 0 | `Z→z`, `0xe2→z` | zh→z（大写槽用于内部规范键） |
| 1 | `A→h` | 配对方向，结合内部表表示 z/zh 组 |
| 2 | `C→c`, `0xe0→c` | ch→c |
| 3 | `B→h` | c/ch 反向组 |
| 4 | `S→s`, `0xe1→s` | sh→s |
| 5 | `D→h` | s/sh 反向组 |
| 6 | `H→h` | h 相关归一 |
| 7 | `F→f` | f/h 组 |
| 8 | `N→n` | n/l 组 |
| 9 | `L→l` | n/l 反向组 |
| 10 | `J→n`，并改 `0xe5/0xed/0xf9` 对应槽 | 韵母鼻音组 |
| 11 | `E→g`，并改 `0xe4/0xec/0xf8` 对应槽 | 前后鼻音组 |
| 12 | `K→n`，`0xe8` 相关槽 | 韵母组 |
| 13 | `G→g`，`0xe9` 相关槽 | 韵母组 |
| 14 | `M→n`，`0xf1` 相关槽 | 韵母组 |
| 15 | `W→g`，`0xf0` 相关槽 | 韵母组 |
| 20 | `R→r` | r/l 组 |
| 21 | `O→l` | r/l 反向组 |
| 22 | `Q→g` | k/g 组 |
| 23 | `P→k` | k/g 反向组 |
| 24 | `T→a` | 韵母类 |
| 25 | `V→e` | 韵母类 |
| 26 | `U→o` | 韵母类 |

必须强调：单看此函数可确定**代换字节和值**，但大写槽 A..Z 是内部索引，不应全按字面拼音解释；韵母特殊码的完整语义需与 Phoenix 音节枚举表联调。常见 `z/zh,c/ch,s/sh,n/l,f/h,r/l,k/g` 的存在则由成对写表与 `DPFuzzyMapConvert` 双向规则共同确证。

伪 C：

```c
int get_fuzzy_map(uint32_t enable, uint32_t m, uint8_t map[256]) {
    if (!map) return E_PARAM;
    for (int i=0;i<256;i++) map[i]=(uint8_t)i;
    if (!(enable & 0x10000)) return 0;
    if (m & (1<<0))  map[0xe2]=map['Z']='z';
    if (m & (1<<2))  map[0xe0]=map['C']='c';
    if (m & (1<<4))  map[0xe1]=map['S']='s';
    if (m & (1<<8))  map['N']='n';
    if (m & (1<<9))  map['L']='l';
    /* 其余按上表覆盖；不是链式 if/else，可同时启用 */
    return 0;
}
```

## 6. 点击纠错 `GetCorrectProp`

VA `0x101032550`。严格前置条件：`InputKey/OutputMap/Layout` 有效，触点 `x/y!=-1`，标签 NUL 终止且长度合法，字符在 `a..z`，键宽高非零。

### 6.1 几何归一化

对标签串中的每个候选字母：

```c
dx = (coord[ch-'a'].x - touch.x) * 100 / layout.key_w;
dy = (coord[ch-'a'].y - touch.y) * 100 / layout.key_h;
```

证据为 `0x1010327c4..0x1010327f0`（中心减 `InputKey+4/+8`，乘 100，分别除 `Layout+26/+24`）。所有量都是有符号整数，随后才转 float。

### 6.2 方向模型

静态表以首标签和候选序位索引，取 `int8_t dirClass`。分支精确恢复为：

```c
switch (dirClass) {
case 1: raw = fabsf(dx) * Kx; break;
case 2: raw = fabsf(dy) * Ky; break;
case 3: case 4: raw = (fabsf(dx)+fabsf(dy)) * Kxy; break;
default: keep_existing_or_zero();
}
score = (int)(raw + 0.5);       // 浮点舍入
if (score == 0) score = 16;
out->prop[i] = score * rankDecay;
```

`Kx/Ky/Kxy` 从只读浮点区加载（`0x100398af8/afc`、`0x1002b7e68`），精确十进制值需读取原 Mach-O 常量；不能凭汇编文本臆造。`rankDecay` 由输入 count 算出的半值/序位因子提供。这里的 `prop` 更像**代价/惩罚**而非 [0,1] 概率：结果是整数且零被替为 16。

若触点未知（`-1`），函数走静态邻接表：每字母记录步长 `68` 字节，按 nominal 字符展开预定义邻键权重。故“相邻键”并非用运行时半径遍历，而是静态邻接模板 + 几何分值两路兼容。

## 7. 滑动纠错

### 7.1 26 键 `GetSwipeCorrectProp` — VA `0x101032a14`

前半参数检查及 `dx/dy` 生成与点击版同构。差异在于方向表有 4 类，且先用阈值裁剪：

```c
switch (dirClass) {
case 1: accept = fabs(dx) < T0; metric=fabs(dx); break;
case 2: accept = fabs(dy) < T0; metric=fabs(dy); break;
case 3: accept = fabs(dx)+fabs(dy) < T1; metric=fabs(dx)+fabs(dy); break;
case 4: accept = fabs(dx)+fabs(dy) < T2; metric=fabs(dx)+fabs(dy); break;
}
if (accept)
    out->prop[i] = roundf(fabs(dx) * fabs(dy) * Kswipe); // 汇编连续两次 fmul
else
    out->prop[i] = 0; // 剪枝
```

证据：`0x101032d5c..0x101032e2c` 的 `fcmp/fabs/fadd` 四分支；`0x101032e3c..0x101032e4c` 两次 `fmul` 后 `+0.5`、`fcvtzs`。这解释滑行输入为何比点击更强地排除偏离轨迹方向的键：先方向门限，再二维乘积惩罚。

### 7.2 9 键 `GetSwipeCorrectProp9Key` — VA `0x101032fa8`

只利用横向偏差：

```c
adx = abs((centerX - touchY_or_axisField) * 100 / key_h_or_axisSize);
if      (adx >= 36) prop[i] = 16;
else if (adx >= 26) prop[i] = 32;
else if (adx >= 16) prop[i] = 48;
// <16 保持原值/默认值
```

这里第三参数是 NUL 终止的 `uint16_t` 键串；第二参数并非前述单触点 `InputKey` 视图：`+32` 为 `Layout*`、`+40` 为中心表指针、`+8` 为轨迹轴坐标。函数从中心表记录首个 `int32_t` 减 `arg1+8`，再除 `Layout+24`，因此是按该布局定义的单轴偏差。候选数通常取标签长度；首键为 `'7'/'9'` 时目标上限 4，否则 3，并在长度未达到 5 时直接成功返回。阈值 `0x24/0x1a/0x10` 与写值 `0x10/0x20/0x30` 是硬编码事实。

## 8. `LayoutImp` 实现层

### 8.1 关系

`LayoutImp::C1(0x101035688)` 只设置虚表和 `core`，所以它是接口适配器/策略对象，不拥有算法副本。`GetLayoutCoord(0x1010356b4)` 读取 `[this+8]` 后尾调用 `KeyLayout::GetLayoutCoord`。

### 8.2 `GetKeyMapping` — VA `0x1010356cc`

它读取 `InputKey+8,+12,+16,+20,+24,+28` 和 `KeyLayout` 状态，完成：

1. 核心指针与输入输出校验；
2. 根据输入 kind/键盘类型选普通、双拼、9 键、多语种；
3. 调 `KeyLayout::KeyMapping`；
4. `bool` 参数控制是否执行纠错/滑动权重补充；
5. 保持统一错误码和日志。

因此上层应只依赖 `LayoutImp`，而把语言表、用户自定义双拼与几何模型都留在 `KeyLayout`。

### 8.3 `KeyMapConvert` — VA `0x1010359e4`

`mode==0` 时以 `(count,src,dst)` 尾调一个转换函数；`mode==1` 时改换参数顺序尾调反向转换函数；其他 mode 返回 0/不处理。此处是内部 token 序列与外部 key map 表示的双向适配，不做几何评分。

## 9. 完整链路与可移植伪 C

```c
int process_key(LayoutImp *imp, const RawEvent *ev, CandidateSink *sink) {
    InputKey in = normalize_event(ev); // tagged union：tap/swipe/key-sequence
    LayoutCoord centers[26];

    if (VerifyLayout(&ev->layout)) return E_PARAM;
    if (ev->nine_key) Set9KeyCoord(&ev->layout, centers);
    else              Set26KeyCoord(&ev->layout, centers);

    // UI nominal key 或轨迹经过键；中心查询用于对齐/纠错
    LayoutCoord c;
    imp->GetLayoutCoord(in.nominal_key, &ev->layout, &c);

    OutputMap om = {0};
    int rc = imp->GetKeyMapping(&in, &om, ev->enable_correction,
                                ev->is_swipe);
    if (rc) return rc;

    // KeyLayout 内部逻辑的等价展开：
    int16_t tokens[MAX_MAP], canonical[MAX_MAP];
    int n = map_label_to_tokens(in.label, ev->keyboard_mode, tokens);
    if (ev->double_pinyin) {
        if (custom_dp_enabled)
            CustomDPKeyMapping(ev->dp_state, in.label[0], tokens, canonical);
        else
            DPKeyMapping(ev->dp_state, in.label[0], tokens, canonical);
        DPFuzzyMapConvert(tokens, canonical, ev->fuzzy_flags);
    } else {
        uint8_t fuzzy[256];
        GetFuzzypyMap(ev->fuzzy_enable, ev->fuzzy_mask, fuzzy);
        for (int i=0;i<n;i++) canonical[i]=fuzzy[(uint8_t)tokens[i]];
    }

    if (ev->enable_correction) {
        if (ev->is_swipe && ev->nine_key)
            GetSwipeCorrectProp9Key(&in,&om,n);
        else if (ev->is_swipe)
            GetSwipeCorrectProp(&in,&om,n);
        else
            GetCorrectProp(&in,&om,n);
    }

    // Phoenix 后续：规范音节进入词图/语言模型；几何 prop 作为键盘观测代价
    return phoenix_decode(canonical, n, om.prop, sink);
}
```

### 数据流

```text
触摸/滑行事件
  → UI 布局 + InputKey(tagged union)
  → VerifyLayout
  → Set26KeyCoord / Set9KeyCoord（中心表）
  → nominal key code / 轨迹键序列
  → LayoutImp::GetKeyMapping
  → KeyLayout::KeyMapping
       ├─普通/9键：keylayout_getmapcommon_sub
       ├─双拼：CustomDPKeyMapping 优先，DPKeyMapping 回退
       ├─模糊音：GetFuzzypyMap / DPFuzzyMapConvert
       └─几何：GetCorrectProp / GetSwipeCorrectProp(/9Key)
  → canonical syllable token + integer observation cost
  → Phoenix 词图、词频/语言模型联合打分
  → 候选排序与回显（必要时 DPSyllablToOriLabel 恢复原键序）
```

## 10. 可移植实现要点

1. **保持 16-bit token，不要提前 UTF-8 化。** 标签串和内部 `0xe0..0xf9` 音节码均以 `uint16_t` 处理，0 终止。
2. **几何算法保持整数归一化。** 原实现先 `*100/sz` 再转 float；直接用浮点像素距离会改变边界和排序。
3. **代价方向不要弄反。** `prop` 是整数惩罚/观测成本，0、16 等具有哨兵/下限意义，并非概率百分比。
4. **9 键与 26 键不可共用同一纠错函数。** 9 键是一键多字母并有专门分桶规则；26 键有方向类和二维模型。
5. **模糊映射必须是可叠加 bitmask。** 各 bit 独立覆盖同一 256 表，配置组合的覆盖顺序应与原函数一致。
6. **自定义双拼事务更新。** 先完整解析临时表，再原子替换；任何非法键、字段数或冲突都不能留下半张表。
7. **布局锚点按三行保存。** 不要假定等宽全矩形；第二、三行横向缩进是 `Layout` 的设计能力。
8. **表驱动语言扩展。** Devanagari 路径证明几何层可复用，语言规则应由 `KeyMap`/token 表注入。
